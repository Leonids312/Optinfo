# Optinfo 服务端运行与接口

Optinfo 面向单人、多设备使用。FastAPI 提供认证接口，SQLite WAL 保存简报、收藏、兴趣和短期对话，官方 DeepSeek Harness SDK 负责内容分析和问答。API 契约见 [API.md](API.md)。

## 启动

需要 Python 3.10 或更高版本。将源码部署到配置指定的 Optinfo 目录；把数据、设备令牌和 Harness 运行目录放在 Git 目录之外或明确忽略的目录中。

```sh
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
# 从权限受限的私有环境文件读取部署配置。
cd backend
../.venv/bin/uvicorn optinfo.api:app --host 127.0.0.1 --port 8765 --workers 1
```

端口只是示例，部署前检查占用。API 仅绑定回环地址，通过已有 Tailscale Serve 的独立端口或明确隔离的路径访问。不得重置 Tailscale Serve、替换已有 Kazumi 路由、修改 Kazumi 容器或复用其数据库。Tailscale 设备须属于获准访问的私人网络；客户端仍须配置独立的 Optinfo 令牌。

| 环境变量 | 作用 |
| --- | --- |
| `OPTINFO_DB_PATH` | SQLite 文件绝对路径；默认 `backend/data/optinfo.sqlite3` |
| `OPTINFO_DATA_DIR` | 未逐项指定路径时的数据根目录 |
| `OPTINFO_CHAT_DIR` | 每个聊天的 UUID 子目录，必须是 Optinfo 专属位置 |
| `OPTINFO_MEDIA_DIR` | 原文图像缓存；默认位于数据库同级 `media/` 目录，经认证接口读取 |
| `OPTINFO_TOKEN_FILE` | 设备令牌文件路径，推荐使用权限受限的私有文件 |
| `OPTINFO_TOKEN` | 也可直接从进程私有环境提供令牌；优先于令牌文件 |
| `OPTINFO_CORS_ORIGINS` | 逗号分隔的允许网页来源；原生客户端通常不需要 |
| `DEEPSEEK_API_KEY` | 仅服务端使用，不写入仓库、客户端或日志 |
| `OPTINFO_HARNESS_DIR` | Harness 生成任务运行目录 |
| `OPTINFO_DSH_MODEL` | Harness 使用的模型，由当前官方服务支持情况决定 |
| `OPTINFO_MODEL_TIMEOUT` | Harness 单次模型请求超时秒数 |
| `OPTINFO_GENERATION_MAX_TOKENS` | 生成首轮输出预算，默认 8000，限制为 8000–12000；达到长度上限时至多追加一次 12000 预算重生成 |

使用单个 Uvicorn worker。聊天按资讯加异步锁，多设备对同一资讯提问会串行处理。生成进程和 API 可以同时访问数据库；SQLite 使用 WAL、外键和 30 秒繁忙等待，写入版次使用 `BEGIN IMMEDIATE`。后续若扩展到多用户、多 API 副本，应改用跨进程任务队列与分布式锁。

## 内容与偏好

用户内容要求统一维护在 `skills/optinfo-content/SKILL.md`。`optinfo.editorial.content_policy()` 每次模型请求读取其中的生成规则，注入 Harness 系统提示；不把维护说明、私有配置或凭据传给模型。部署必须同时包含 `backend/`、`content/` 和该 skill。以后修改选题、来源、回溯或文风时先更新同一文件，再同步采集与筛选行为。文章评价聚焦技术与业务，来源信息保留在来源字段，正文不添加固定的可靠性说明段。

期刊目录、分区依据和检索预算见 [JOURNAL_SOURCES.md](JOURNAL_SOURCES.md)，企业入口与历史窗口见 [INDUSTRY_SOURCES.md](INDUSTRY_SOURCES.md)。企业分区默认最多 4 条：优先不同公司各一条，按 7、30、90、365 天由近及远寻找未审核内容，仍不足时才允许同一公司第二条。DOI、规范化 URL、arXiv 编号和同公司近日期原始标题参与跨日期去重；成功发布与筛掉的候选持久记录，失败候选保留重试机会。

每轮仍受候选数量上限约束。选择诊断记录正文尝试数、分析调用数，以及已访问和未访问的企业时间窗口；达到上限但未完成搜索时标记 `budget_exhausted`，不能把本轮正常结束理解为已检索完全部历史。

部署扩容后可用 `python -m optinfo.cli fill-industry --date YYYY-MM-DD --industry-target 4` 补充**当天已有版次**的产业区。它只追加缺少的条数，保留原有快照、排序位置、生成时间、状态和研究重试记录；补充诊断单独存于 `metadata.industry_fill`。已达到目标时直接返回，不再调用模型。常规每日生成仍使用 `generate`。

所有业务日期按 `Asia/Shanghai` 计算，与服务器操作系统时区无关。每日 04:00 的生成任务由部署层调度；失败后的补跑仍使用明确的版次日期。API 不启动重复的生成定时器。

每天保存一份版次。`ready` 版次重复提交返回 `False`，不会替换已完成的内容和排序。`partial` 版次重试会复用当天成功条目，仅处理此前诊断记录中的失败、暂缓或缺失候选，不重新挑选一批新资讯。失败候选无法从来源重新获取时继续保留 `partial`；缺少可识别的重试范围则明确报错。重试完成后合并提交快照，避免因某一条持续失败而不断增加资讯和模型费用。数据库也保留独立采集的重大事件。新增重大事件可以追加到已完成日期，不改动其原有条目快照。内容源故障不得伪造正常条目或模型答案。

模型输出须通过严格 JSON 和字段校验；校验失败或达到输出长度上限时，只能依据相同原始证据重新生成一次，两类恢复共用最多两次请求的限制，不补造截断字段。模型请求超时等其他运行错误不会在条目内部自动重复请求。即使本轮没有可发布资讯，只要部分候选已成功审核，也会保存审核记录，避免每小时对同一批已筛掉的内容重复计费。

CLI 输出安全诊断：来源名称及错误类型、失败条目 ID、阶段、异常类型、完成原因、重试次数和成功审核数量；不输出原始模型回答、异常正文、提示词或密钥。每日版次元数据保留逐项诊断，重大事件任务也将同样的失败字段写入私有运行日志。全部来源不可用时报告 `SourceCollectionUnavailable` 和 `collect` 阶段，已有内容不变。

兴趣设置按生效日期保存历史。当天最后一次保存的完整选择于上海时间次日 00:00 生效，因此次日 04:00 使用新权重；当天已生成版次保持原样。空数组表示明确取消全部勾选，不能误判为“尚未设置”。`bootstrap.effective_date` 非空时，编辑界面应显示 `pending_topics`，否则显示 `active_topics`。

`GET /api/briefing` 不带日期和检索条件时读取今天。今天没有生成时返回 `not_generated` 和空列表，不悄悄把旧简报当作今日内容。省略日期且提供关键词、期刊、公司或收藏筛选时查询历史；显式日期始终限定当天。期刊参数接受目录中的 ID 或期刊名称。公司使用稳定 ID。

收藏独立于版次快照、企业资料和对话记录存储。重试生成、重新整理企业资料、清除对话不会删除收藏。

## 论文证据与数学排版

解析器保留 HTML 中的 TeX/MathML 数学信息，并提取最多 32 个原文候选图及其图注、正文引用和来源。Harness 必须从候选 ID 中选择支撑研究结果的关键图，给出中文图注与选择依据；不能自行构造图片 URL。公式在摘要、正文、图注和问答中使用 LaTeX 分隔符，JSON 中的反斜线必须正确转义。

HTML 缺少可用正文或图片时尝试可合法访问的原文 PDF。PDF 限制为 25 MB、80 页；只在识别到图注的页面建立候选，无法确定裁切边界时保留并明确标注原文整页。PDF 文本中的公式提取可能不完整，模型不得据此猜造原式。原始图片或 PDF 页规范化为 PNG 后按内容哈希保存，图片读取仍需设备令牌。不能取得必要正文、关键图或合格中文说明的论文保留诊断并重试，不作为完整解读发布。

显式的论文内容修复会同步更新条目与已存版次中的内容字段，保留条目 ID、日期、排序、收藏和对话；这与普通每日版次的幂等提交分开处理。部署和修复前使用 SQLite online backup，验证后按私有数据保留策略清理临时备份。

通过已载入私有服务配置的环境执行 `python -m optinfo.cli repair-papers --limit 20`。默认跳过已经完成本次证据升级的论文；可重复执行恢复失败条目，或用 `--item-id` 限定单篇，`--force` 明确要求重新核对已升级内容。修复与日常生成共用进程锁，避免同时改写；API 阅读仍可用。

仅修复旧内容的数学排版时使用 `python -m optinfo.cli repair-math-only --limit 20`，同样支持重复的 `--item-id`。该操作不重新抓取来源或选择图片，仅允许为现有文本插入公式分隔符，并在公式内将不兼容的 `\AA` 规范为等价的 `\mathring{A}`。服务逐字核对原文、既有公式及 URL，拒绝模型改写事实或单位；每批字段最多尝试两次。失败保留原内容并标记排版待修复，后续可再次执行此命令；不触发图片证据重采集。新生成内容也检查裸露的等式、不确定度及上下标符号。

## 对话生命周期

同一资讯只对应一个活跃会话，设备共享历史。会话从首次提交问题时开始计时，七天后到期；继续提问不会延长到期日。模型只收到当前资讯和必要的历史内容，不接收学校密码或设备访问令牌。

聊天在调用 SDK 前登记到数据库，所以进程异常退出留下的资源也能按期清理。服务启动、每小时维护及每次读取/提交聊天都会处理到期记录：删除 `chat_messages` 与 `chat_sessions`，把对应 SDK 目录放进持久清理队列，执行 Harness 清理钩子后删除 UUID 子目录。失败的外部资源清理保留队列并重试。目录删除前验证 UUID、解析后的父目录和专属根目录，拒绝跨目录或符号链接逃逸。

正在回答的会话通过数据库租约保护，API 和独立维护命令均不会同时删除其资源。若进程中断，租约在十五分钟后自动过期。如果回答期间会话达到七天，到期内容不再重新保存，客户端收到可重试提示。模型调用失败返回 `503`，不编造回答，也不保存一条虚假的成功交流；客户端须保留输入框问题。

缺少设备令牌时，受保护接口返回 `503`；令牌错误返回 `401`。`/api/health` 不需要认证，仅公开 `status`、`version`、`generator_ready`，不公开路径、主机地址、密钥或上游错误正文。`generator_ready` 表示必要 SDK 和配置已存在，不代表所有资讯源或最近一次模型调用成功。生成诊断应从私有运行日志和版次元数据排查。

## 备份与验证

备份使用 SQLite online backup API，或停写后同时备份数据库及其 WAL 文件；不要在运行中只复制主数据库文件。设备令牌与备份应另行保存。每次发布先运行：

```sh
python -m pytest backend/tests -q
```

测试覆盖认证、上海日期边界、次日兴趣生效、空选择、版次幂等、不完整生成重试、历史筛选、收藏持久性、七天消息和 SDK 文件删除、清理失败重试、进程中断资源到期及真实失败响应。部署后还需验证手机流量加 Tailscale 可访问独立入口，以及 Kazumi 原入口前后均正常。
